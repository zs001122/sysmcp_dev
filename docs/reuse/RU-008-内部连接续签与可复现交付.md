## 契约与评估

| 维度 | 结论及证据 |
|---|---|
| 需求适配 | 满足：BIZ 原生 CLI 已能按当前主体许可签发短期令牌；只补原登记的管理 API 更新及回读，不建设新身份系统 |
| 公开边界 | 满足：BIZ 发布独立私有导出文件；GOV 只消费该文件及自有管理资料，不接触员工映射、业务凭据、许可库或签名私钥 |
| 依赖和制品 | 满足：BIZ 使用原 0.9.2 固定 wheel；GOV 有自身 pyproject.toml、uv.lock、.venv，运行工具无第三方包；CI 构建后端及传递依赖另按六包版本和哈希固定 |
| 接口兼容 | 满足当前版本：按现有 MetaMCP 2.4.22 的登录、服务 get／update 契约更新，保留原对象和非令牌字段；升级须重新验证 |
| 失败和审计 | 满足限定用途：本轮最多一次更新 POST，响应异常只回读；同步未确认不记成功，保留上次成功和到期事实；不重试业务写入 |
| 验证 | 29 项独立 GOV 测试、本地 CORE 4 项及 BIZ 1940 项通过；现场两轮不同令牌同步成功，第二轮由 timer 自动触发；网关缺确认请求前置拒绝且 T100 请求数为 0，见运维验证 |
| 维护成本 | 最小新增单文件同步工具和三份 unit；版本固定，不引入跨模块数据库、通用恢复框架或新日常业务脚本 |
| 已知限制 | 同步工具只解析导出 JWT，原生验签仍由 BIZ 完成；MetaMCP 更新无条件版本控制，人工改登记需停 timer 并等待在途任务；无宿主实际重启演练，不等于完整发布验收 |

## 决定与产出

结论：优先复用当前合格 BIZ 公开 CLI，旧仓候选不复用；GOV 的缺失同步能力最小实现。无需复制已有业务实现，也不沿用旧来源的执行许可。

契约及运行边界见 [续签说明](../../projects/gov/docs/connector-renewal.md)，实际轮次、固定制品及常驻证据见 [运维验证](../../projects/gov/VALIDATION-operations-20261021.md)。停用定时器会停止续签，但不会立即撤销已签令牌；即时撤权仍走 BIZ 主体许可或 GOV 服务停用。此结论不提高真实身份、账号效果、business-validated 或 published 状态。
