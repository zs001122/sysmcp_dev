# BIZ-ADP 开发规范

本规范用于 `/data/projects/sysmcp_dev` 中的业务适配项目。目标仍是让企业 AI 受控访问既有业务系统，按各系统明确的执行身份保留上游实际权限并可追踪；先完成一个真实系统的一个只读工具，再推进原一期的一读一低风险写入。

当前首个候选为 account_mt_v2 中的 T100 本人员工档案查询，已按 RU-001 限定为离线适配开发；真实权限与运行准入尚未通过。后续不创建占位 BIZ 项目，禁止未经评估直接复制旧 ERP/OA/CRM 演示代码。旧资产按 [REUSE-01旧模块复用准则](旧模块复用准则.md) 优先评估其当前适用部分；模拟用户与演示验收、仅凭系统凭据存在或连通，不能作为真实业务授权依据。T100的service-account模式已由用户明确，按[ADR-003](架构决策-003-T100服务账号授权.md)执行本人授权，不再要求员工T100凭据。Core 工程烟测、网关选型和本文均不表示业务链路已经闭环。

## 1. 项目边界

每个业务系统建立一个独立项目 `projects/biz-<system>/`；一个项目可包含该系统的多个工具，但不得混入其他系统的凭据、API 或规则。项目是源码、契约、依赖、测试和制品的独立边界，不机械等同于一个运行进程。

```text
projects/biz-<system>/
├── pyproject.toml                 独立包、依赖、开发命令
├── uv.lock                        独立锁定依赖
├── README.md                      系统、负责人、接入条件与验证入口
├── src/biz_<system>/              工具、API 客户端、配置和启动入口
├── tests/                         合成数据、单元及 HTTP 契约测试
├── docs/tool-contracts.md         工具输入输出、权限、分页和错误映射
├── docs/service-release.md        给 GOV 的去敏服务发布描述
└── .env.example                   配置名称与示例，无真实凭据
```

每项目使用自己的虚拟环境，可单独安装、构建和测试；仅依赖其他项目公开发布的包与接口，禁止跨目录导入内部源码或共用数据库表。真实凭据和业务数据不入库。跨项目共进程部署必须经过边界评估；共享凭据、不同信任域、管理员权限、写操作、独立故障或发布节奏均应拆成独立 FastMCP 运行单元。T100持有管理员服务key，因此默认独立部署。

### 1.1 向 GOV 提交的发布接口

`docs/service-release.md` 是 BIZ 与 GOV 之间的去敏交付契约，至少声明服务逻辑 ID、制品及版本、环境地址引用、协议 Profile、工具白名单与契约版本、身份承载要求、健康检查、超时、回滚版本、负责人和 BIZ 验证证据。GOV只接收这些发布元数据，不接收业务源码副本、真实 URL 密钥、上游业务凭据、员工映射、授权清单、完整业务响应或业务审计库。

BIZ 的模块验收状态与 GOV 的登记、组合、发布状态分开记录。新增或变更项目还须遵守 [模块边界与接口约束](模块边界与接口约束.md) 和 [GOV 服务接入规范](../projects/gov/docs/service-onboarding.md)；通过公开契约和兼容测试扩展，不能让 GOV 或其他 BIZ 项目依赖本项目内部结构。

## 2. 使用原生 FastMCP

- 使用 Python 3.12、FastMCP 4.0.10，与当前 Core 基线一致；依赖由本项目 `uv.lock` 固定。
- 通过 `sysmcp_core.create_service(name, auth=auth_provider)` 创建原生 FastMCP 服务；`auth` 必须显式提供，真实入口不得使用空认证或测试验证器。
- 使用原生 `@mcp.tool` 注册 `async def` 工具，参数和返回值使用明确类型或 Pydantic 模型，由框架生成输入输出 Schema。
- 使用异步 HTTP 客户端并管理其启动、关闭及取消；异步工具内不得调用阻塞网络方法。
- Core 当前只是轻量服务工厂；业务授权、合法凭据、耐久审计等能力必须分别接入并验证，不能由工厂存在推断已经具备。
- 不整体搬入旧通用执行管线；其中当前需要、可独立提取的逻辑须按REUSE-01评估后复用。不新增自制 MCP 协议层、工具注册框架或并行管理平台。业务项目负责本系统的 API 翻译和语义；可复用需求出现后再提取公共代码。

## 3. 离线开发与真实接入

离线开发、构建和 `biz-validated` 验收不依赖真实 IdP 或业务服务器。使用仅限测试的签名身份、受控映射、临时私有文件、动态合成密钥和模拟上游，验证真实产品认证/授权/报文/审计链；模拟上游必须捕获产品客户端实际构造的 HTTP 请求，不能只让假 Reader 返回期望员工。测试认证器、私钥、Token、service key 和测试数据不得进入产品 wheel 或真实运行装配；不为此新增 IAM 平台。

真实身份来源缺失不阻塞离线 `biz-validated`，但不能因此装配默认允许、固定员工或信任任意 Header 的真实入口。下述真实联调资料是后续真实接入条件，不是离线组件开发的前置条件。

真实联调前在项目 README 中记录：系统与测试环境、业务和接口负责人、API 文档、稳定业务用户 ID、明确的per-user/delegated/service-account模式与凭据取得方式、一个只读API、调用者授权范围和允许/拒绝测试对象；T100使用已明确的服务账号，准备两个不同本人员工映射及未获准用户。

候选已有明确报文和用途时，可先依据复用评估建立隔离离线开发包，列出未确定项，不配置真实业务入口。接入真实运行前，按声明模式取得分层允许/拒绝结果。per-user/delegated比较原API用户权限；T100 service-account比较原API服务key有效/失效，并在BIZ验证两个MCP用户的本人范围。禁止全量读取再本地过滤代替精确授权查询；`operator`、`owner`、用户Header不能成为受信调用身份。

## 4. 身份、凭据与业务权限

- 用户身份来自已验证的入口上下文。员工号只可来自明确选定的权威签名 claim，或由受控 `issuer+subject` 唯一映射取得；签名有效不等于任意 claim 都有权指定员工号。每个系统声明选用来源、校验条件与变更责任，不混用或隐式回退。工具参数不得决定主体、原客户端、代理客户端或凭据引用。
- 当前 T100 仅实现受控 `issuer+subject` 映射；普通 Header、姓名、邮箱、MetaMCP Key、工具参数，以及虽已签名但未被选为权威来源的 `employee_no` 均不能覆盖映射。额外工具参数直接拒绝；同一身份出现多条员工映射视为配置无效，不取第一条或按姓名猜测。
- T100 的查询对象以受控运行配置中的 `enterprise_id` 与授权映射得到的 `employee_no` 共同确定。模拟上游须断言实际请求中的 `datakey.EntId` 和 `employee_no` 完全相等；即使上游支持模糊匹配，返回也必须恰好一条且员工号完全相等。姓名仅用于展示，不用于身份、授权或目标选择。
- 每项目显式声明执行模式及目标/用途。per-user/delegated使用用户或合法委托凭据；T100 service-account在调用者本人许可通过后使用配置的服务管理员key。缺映射、缺许可或凭据缺失即拒绝，禁止隐式切换模式或回退管理员账号。
- service key 的内容只能在调用者本人许可通过后读取；初始未映射、停用、无许可等拒绝须同时证明零上游请求和零 key 内容读取。健康检查只看必要的凭据文件元数据。已合法授权后再发生撤权时，要按实际阶段记录，不能伪报此前未读 key 或未调用上游。
- MCP 入口 Token 不原样透传给业务系统；Token A/B/C 的受众与来源边界由身份和集成契约确定。
- 原业务系统检查实际执行身份的权限。用户/委托模式保留其原用户权限；已明确的T100服务账号模式由BIZ控制调用者工具/本人范围，上游检查服务身份，不能宣称员工ERP细粒度权限已继承。服务管理员权限不授予MCP用户。
- 只连接配置中批准的目标、方法与路径；工具不接收任意 URL、认证头或 SQL，禁止自动跨目标重定向。

## 5. 工具契约

每个工具在 `docs/tool-contracts.md` 登记稳定名称、用途、只读/写入属性、输入输出 Schema、原 API 映射、权限条件及以下规则；发布前由契约测试核对。

| 项目 | 约定 |
|---|---|
| 输入 | 显式类型、必填项、长度/数值/枚举边界；不支持的参数拒绝，不静默截断或扩大范围。 |
| 输出 | 类型化结构；列表统一返回 `items` 和可空 `next_cursor`，详情返回明确模型；字段白名单及嵌套结构逐项定义。 |
| 空结果 | 合法查询无数据返回空 `items`；认证失败、无权、上游故障不得伪装成空成功。 |
| 分页 | `limit`、游标作用域和结束条件明确；默认最多 50 条、上限 100 条，不自动遍历全部页；不同上限须在工具契约中说明。 |
| 时限 | 初始连接超时 3 秒、单次工具总预算 10 秒；分页、重试均占用总预算；不满足时应先调整并记录契约。 |
| 错误 | 使用原生 `ToolError` 暴露稳定错误码及去敏说明；至少区分参数错误、未认证、业务无权和上游不可用，内部异常保留服务端定位信息。 |
| 追踪 | 关联 request/trace ID、可信用户及客户端来源、工具、业务请求引用、拒绝阶段与结果；不记录 Token、密码、原始敏感入参和完整业务响应。 |

HTTP 状态与业务错误码的映射必须逐项写明。超时或取消只表示等待结束，不能据此宣称原系统未执行；默认不自动重试，确需只读重试时明确允许错误、次数及预算。

只读联调也需要可核对的耐久调用记录：调用前无法登记则不发业务请求；调用后记录失败保留待核对事实，不伪报成功或未执行。相关能力未接入时，只能进行明确标注的模块测试。

## 6. 写入单独验证与发布

首个真实闭环优先发布只读工具，确认接口没有隐含写入副作用。用户明确要求的写能力可提前完成隔离离线开发，不能因此跳过真实写接口验证或随只读服务自动发布。当前 T100 本人密码重置按 [ADR-006](架构决策-006-T100本人密码重置.md) 推进。写入须单独设计：用户确认、原系统原子权限检查、业务幂等键作用域、同键不同输入冲突、结果查询及回退。

2026-10-08 范围对齐：用户已明确授权的 T100 内部真实写测试，按 [AGENTS.md](../AGENTS.md) 的动作、目标范围、显式确认、审计及未知占用约束作为当前阶段例外推进；它不表示已经满足正式写发布的幂等条件。当前 T100 仅实现请求编号防重和 unknown 目标占用，跨请求业务幂等仍 pending。本轮不实施 schema 迁移或自动重试，后续方案记录在 [DEC-002](项目讨论与决策记录.md#dec-002biz-t100-交付收尾与写入幂等边界) 的待讨论部分；正式发布仍须完成本节契约及对应验证。

业务幂等键与请求防重放标识分开；并发同键最多产生一个业务对象。结果未知时标记待核对，不盲目重试；除上述明确授权的限定内部测试外，没有原系统支持及验证证据，不开放真实写执行或 GOV 发布；可用合成身份和模拟上游验证 BIZ 写契约，并准确标注候选报文与实际接口的差距。只读通过不等于原一期完成。

## 7. 分层验收与产出

状态按证据分别签收，不把真实服务器的可用性当成所有开发工作的共同门槛：

| 状态 | 需要证明 | 不包含 |
|---|---|---|
| `biz-validated` | 独立制品及声明的离线契约通过，包含身份、员工映射、实际序列化请求、拒绝、失败和审计矩阵 | 不要求真实 IdP 或业务服务器；不等于真实权限或 GOV 发布 |
| `business-validated` | 可信真实个人身份能取得权威员工号或唯一受控映射，原 API 与 BIZ 分层授权、本人隔离及审计通过 | 不由模拟测试或 GOV 发布状态推导 |
| `published` | GOV 实际登记、工具白名单、private endpoint、入口拒绝/启停和两跳契约通过 | 不自动代表原业务的真实权限已经验收 |

`business-validated` 与 `published` 是独立维度，不能互相替代；真实可用闭环需要两者各自的对应证据。没有真实个人身份时继续完成离线验收，真实业务状态不提升；发布状态按 GOV 自身证据独立判定，未执行登记与两跳时保持未通过。

| 层次 | 必须验证 | 结论边界 |
|---|---|---|
| 单元 | 参数边界、输出模型、错误映射、空结果、分页结束及敏感字段处理 | 仅证明本地逻辑；合成身份不证明真实权限。 |
| HTTP 契约 | 本地替身核对方法/路径/参数、响应归一、超时取消、越界目标拒绝；前置拒绝时业务请求为 0 | 仅证明 Adapter 与已约定 API 的交互。 |
| MCP/网关联调 | 原生工具发现/调用、认证、已声明的兼容协议基线、来源区分、拒绝与追踪；固定组合版本 | Core 烟测或单组件通过不等于 MetaMCP 组合通过。 |
| 真实业务 | 按模式验收：用户/委托模式做原用户权限对照；T100服务账号模式验证两员工本人隔离、未授权前置零请求及原API服务key拒绝；各模式均核对撤权、身份、审计与调用事实 | 必须使用获准真实测试环境，由业务负责人确认；模拟通过不能替代。 |

T100 的全部离线场景、请求计数与审计断言见 [离线身份链验收矩阵](../projects/biz-t100/docs/offline-acceptance.md)。使用本轮独立的合成签名密钥、Token 与 service key，不迁入真实凭据。测试按请求 ID 核对审计中的可信主体、员工号、固定企业与工具及结果；终态 `upstream_attempted` 只表示进入业务 Reader，实际 HTTP 请求数由模拟上游另行捕获。终态写失败保留未决记录，不推断未派发，也不自动重放。

每次交付更新工具契约、服务发布描述、测试入口和去敏验收记录，注明代码/依赖版本、环境、已执行/未执行项与剩余阻塞。业务系统自身拒绝应如实记录已发生的调用；只有入口或 Adapter 前置拒绝才要求业务请求为 0。GOV接入变更必须做工具Schema、身份、错误和直连/两跳对照；受影响的既有服务完成回归前，不扩大发布范围。

涉及旧模块时，交付记录须链接复用评估，列出源commit/路径、实际提取范围、保留和改变的行为、目标包及验证结果。评估结论与新项目验收分开记录，不以“沿用旧测试”代替当前接口和真实业务验证。
