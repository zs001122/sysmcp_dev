# RU-003：T100 本人密码重置复用评估

日期：2026-09-29。规则：[REUSE-01](../旧模块复用准则.md)。状态：来源只读评估与限定适配完成；v0.4.0离线候选通过验证（全项目457项测试），真实写入未准入。实际证据见 [本轮验证](../../projects/biz-t100/VALIDATION-reset.md)，不继承旧测试结论。

评估分工：plans_evidence 检查确认、耐久去重与未知结果原语；runtime_architecture 独立检查旧 T100 重置接口及报文；当前实现与验证由主代理协调。业务和接口维护方的真实签收不由代理代替。

## 1. 当前需求与目标边界

用户已确认在 `projects/biz-t100` 增加本人密码重置。开发仍归同一独立项目，使用独立 reset MCP 工厂，并按写权限、凭据和故障边界作为独立运行单元管理；不把写工具加入现有只读服务，不包含 OA、停用、建号或审批。

本轮工具为 `reset_my_t100_password(confirm=true, operation_id=UUID)`：只接受严格显式确认与稳定操作 ID，不接受姓名、员工号、账号 ID、新密码或凭据参数。要求独立 scope `t100:password:reset:self` 和默认 `false` 的 `allow_password_reset`；读权限不隐含写权限。

员工只取自可信 `issuer+subject` 受控映射。写入另需明确受控 `t100_account_id`，`PasswordResetGrant` 同时承载 `employee_id` 与独立 `account_id`，不能令二者默认相等。企业来自固定运行配置，操作库持久绑定身份、客户端、企业、员工、账号、工具及操作 ID。`confirm=true` 表示本次工具输入的明确写意图，不授予权限，也不等于新的身份验证或已发生人工二次审核。

操作状态与审计必须耐久记录后才能考虑派发；派发前重验授权和目标；同 ID 不重复派发，未知结果锁定原员工及物理账号目标，不自动重试、不允许换 ID 绕过。详见下文旧→新差异与验证项。

**当前仅允许离线实现与验证。** 旧接口的局部更新和无创建/启用/权限副作用尚未证明，真实个人身份及上游凭据拒绝契约也未闭环。依本轮实现决定，重置客户端未显式注入离线传输时保持 `business_adapter_not_ready`；不提供真实 reset runtime 装配或启动命令，不用布尔开关绕过此限制。独立 MCP 工厂的存在不代表可真实部署写服务。

## 4. 旧 T100 报文只能有条件适配

并行接口评估的关键证据：

- [旧服务名](/data/projects/account_mt/t100/core/t100_api.py:46)为 `user.account.create`；旧说明将新增/修改合在同一接口，不能由名字或一次返回码推断仅修改现存账号。
- [builder](/data/projects/account_mt/t100/core/t100_api.py:155)区分 `gzxa001`（账号）与 `gzxa003`（员工）；[旧 update](/data/projects/account_mt/t100/core/t100_api.py:557)却把账号赋为员工号。本次必须显式配置 `t100_account_id`，禁止继承该等同假设。
- [重置标记](/data/projects/account_mt/t100/core/t100_api.py:181)为 `password_reset='Y'`；旧 builder 同时默认设置 `gzxastus='Y'`，有附带启用风险，不能复制。旧说明[必填字段](/data/projects/account_mt/t100/docs/user-account.md:13)还要求状态字段，因此最小三字段 patch 是否获支持尚无证据，不能为了满足旧字段表补回启用默认值。
- [旧业务入口](/data/projects/account_mt/api/service.py:61)以姓名和确认参数定位，再提供推定初始密码说明；本次不复制姓名授权、明文密码/说明输出或“初始密码等于工号”假设。
- [旧成功判断](/data/projects/account_mt/t100/core/t100_api.py:128)只检查 `execution.code`；[旧 update 返回](/data/projects/account_mt/t100/core/t100_api.py:573)没有账号目标回显。旧说明[结果核对限制](/data/projects/account_mt/t100/docs/user-account.md:98)明确无账号查询接口，角色明细覆盖/合并语义也未明。不能声称验证了实际账号、密码生效、密码交付或登录成功。

决策为 **报文适配后复用，真实条件未关闭**：离线候选只发送明确的账号、员工及 reset 标记，不附带启用、创建、角色或密码字段；其调用目标和企业由服务配置固定。最小报文的真实部分更新语义必须由接口方提供无创建、无启用、无权限变更副作用的明确依据，并在获准环境验证。

本轮采用严格 ACK-only 语义：仅字符串 `"0"` 或整数 `0` 的明确执行码进入 `upstream_acknowledged`，不能宽松接受布尔值、浮点值或任意字符串转换。`parameter` 只允许缺省/空对象；非空内容没有已确认 Schema，按契约异常和结果未知处理，不臆造目标回显格式。`upstream_acknowledged` 不命名为“密码重置成功”，不返回密码，也不作为实际效果已核对的证据。

旧源码没有证明上游 operation_id 幂等、结果查询、原子授权或无副作用拒绝；本地操作 ID 只约束本服务的派发，不能包装成 T100 自身幂等保证。网络异常、超时、取消、非 JSON、未知执行码或无法解释的响应，按对应派发阶段保守记录，不能简单返回失败并解锁重试。

## 7. 真实接入缺口、产出归属与退出

真实开放前仍需：可信个人身份与写 scope、批准的本人/独立账号映射和重置许可；接口方证明最小 patch 只重置现有账号、不会启用/创建/改权限；明确服务 key 有效/失效和业务拒绝语义；可核对的请求关联及结果未知处理方式。若现有接口无法提供这些保证，应由已有接口服务维护方提供窄重置接口，而不是本项目推测语义、默认启用或另造代理绕过。

当前已有 MetaMCP 容器不等于 reset 已发布。离线 `biz-validated`、真实 `business-validated` 与 GOV `published` 分别取证；真实写入不以工程运行、HTTP code 0 或只读验收代替。旧 HTTP 测试接口也不提供生产 TLS 或写凭据认证证明。

本候选的实现、独立写配置、操作库、测试、工具契约及验证记录留在 BIZ-T100；GOV 只持有去敏发布描述、工具白名单和组合证据。停用时先停止写入口并保留操作库、未知记录和制品，不删除锁或切回旧服务重发；没有兼容且已验收的回滚制品时保持停用。

本轮没有迁入旧实现或运行资产。实际新增范围为BIZ内的reset_client、reset_server、reset_store、三个对应测试文件和一次性direct_reset_check；扩展现有授权模型和scope选择，保持查询工厂兼容。独立wheel与锁摘要、457项测试、两套端口自检和真实缺口见本轮验证及发布描述。本文不能被当作已经批准真实密码重置的凭证。
