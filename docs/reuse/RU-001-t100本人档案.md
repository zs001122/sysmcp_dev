## 3. 决策与允许的动作

决策：**提取或适配后复用报文与校验规则；其他授权/审计仅参考边界，不复制整包。**

允许先在目标独立项目完成有范围的离线适配和测试。组件对身份/授权及耐久审计使用显式注入接口，不默认装配共享 key 或原现场环境。该开发包尚不进入真实业务运行路径。

实际接入条件：合法业务凭据与原系统授权保证、员工映射、身份有效性/撤销策略、错误码说明、指定测试环境及两类权限对照均有证据；再验证 MetaMCP 的员工身份承载及网关组合。API Key 连通不能关闭这些条件。

不提取：OA DisabledAdapter、完整 AccountService、HTTP 写 API、自制 HttpBoundary、登录探针、运行/代理脚本、旧数据库、配置和任何凭据。完整小包不是本候选的最小单元。

## 6. 用户澄清后的授权模式修订（2026-09-29）

用户明确：T100接口由开发人员维护的接口服务提供，调用凭据默认为服务级管理员权限。此前“权限模型未知/必须取得员工T100凭据”的前提不再适用于该候选。按ADR-003采用显式service-account模式，由BIZ根据可信调用者执行本人范围授权；上游检查服务身份，不假称员工OBO或原员工ACL继承。

允许本轮补齐FileServiceAccountAccess及受控配置契约：仅参考原policy.py的精确主体匹配与启停规则，重新实现当前单工具所需最小配置，不复制原目录文件或IT/审批模块。映射和操作许可通过后才读取服务key，每次重读并以内容摘要参与改绑检查；不是个人凭据缺失时的隐式回退。新代码/测试与实际验证结果另记，历史116项证据不改为真实验收。

仍须验证实际服务凭据、开发方API与错误码、受控员工/客户端映射、身份撤销、网关身份承载、真实本人隔离和审计；不再要求两个员工T100凭据差异或询问已确认的管理员权限模型。

本轮实际结果：FileServiceAccountAccess与配置示例已完成；新增74项授权测试及4项HTTP集成测试，合并194项通过。详见[服务账号验证记录](../../projects/biz-t100/VALIDATION-service-account.md)。该结果只关闭本地实现/契约验证项，真实配置、外部接口及网关仍未验收。
