# ADR-006：T100 本人密码重置的独立写边界

日期：2026-09-29。决定：按用户明确授权接入本人密码重置；本轮离线候选契约已达 biz-validated。真实业务、密码交付与 GOV 发布仍未验收，实际测试结论由 [VALIDATION-reset](../projects/biz-t100/VALIDATION-reset.md) 记录，不从历史测试继承。

## 1. 范围与依据

在现有 `projects/biz-t100` 内增加本人密码重置，不新建账号平台，不开放管理员代他人操作，不包含 OA、账号创建、启用、禁用或审批。沿用 [ADR-003](架构决策-003-T100服务账号授权.md) 的显式 service-account 模式：现有接口服务按管理员身份执行，BIZ 独立限制调用者本人范围；这不等于继承员工原 T100 细粒度权限。

本次授权允许离线写工具开发，无需等待真实业务服务器。它不等于允许实际重置任何人的密码。旧接口及去重资产已按 [REUSE-01](旧模块复用准则.md) 评估，来源路径、摘要和取舍见 [RU-003](reuse/RU-003-T100本人密码重置.md)。完整工具、状态与验证契约见 [password-reset](../projects/biz-t100/docs/password-reset.md)。

## 2. 决定

| 边界 | 采用方案 |
|---|---|
| 工程与部署 | 同一独立 BIZ 项目，新增独立 reset factory；按写风险默认独立部署单元，不把写工具加入只读工厂 |
| 工具 | reset_my_t100_password(confirm=true, operation_id=UUID)，只重置本人受控绑定账号 |
| 认证与许可 | 显式 AuthProvider + reset scope + 默认 false 的 allow_password_reset；读授权不能升级为写授权 |
| 目标 | 当前 employee_id 只取可信 issuer+subject 受控映射；另设 t100_account_id，生成独立 PasswordResetGrant.account_id，不默认员工号等于账号 |
| 凭据 | 管理员服务 key 仅在本人许可通过后由服务读取，不进入参数、响应、日志或 GOV |
| 确认 | 严格 true 与规范 UUID；不接受员工、账号、姓名、新密码、key 等参数；确认不替代授权或新鲜身份认证 |
| 状态 | 独立 SQLite 操作库，状态与事件同事务；同 ID 耐久拒重，企业内员工和账号分别占用 |
| 未知结果 | started/dispatched/unknown 持续占用目标；不自动重试、重放、到期解锁或换 ID 绕过 |
| 结果 | 仅 operation_id + upstream_acknowledged，不返回密码，不宣称生效、交付或目标已回验 |
| 当前运行限制 | 上游客户端未显式注入传输则 business_adapter_not_ready；只用模拟传输离线验证，不提供真实 reset runtime 或生产启动命令 |

项目、部署、控制面归属遵循 [ADR-004](架构决策-004-GOV统一服务注册与发布.md) 和 [BIZ 规范](BIZ-ADP开发规范.md)。GOV 将来只管理登记、白名单、namespace/endpoint 与组合证据；业务源码、权限映射、密钥和操作库留在 BIZ。CORE 不增加 T100 语义或通用写平台。

## 3. 不直接复用旧重置执行入口的原因

旧接口实际是 user.account.create，账号 gzxa001 与员工 gzxa003 是不同字段；旧调用把两者强制相等，没有证明该假设。旧 builder 还默认 gzxastus=Y，重置可能附带启用。旧说明将状态列为必填，且创建/修改共用接口，因此尚不能确认一个最小 patch 会只修改密码。

本轮只借鉴经过评估的确认、耐久去重、双目标占用与未知结果测试语义，不搬迁旧运行环境、完整账号服务、凭据、数据库或恢复入口。候选报文只包含受控账号、员工与 password_reset=Y；真实启用前必须由接口方证明专用 reset 或 partial-update 的 no-create/no-enable/no-role-change 保证。不能以重新加入默认启用字段换取表面兼容。

旧成功判断只有 execution.code，未证明目标回显、结果查询、密码交付、登录成功或服务端幂等。本轮只接受字符串 "0" 或整数 0 的 ACK，parameter 仅允许缺省或空对象；未知响应按契约失败处理。查询响应的“恰好一员工且精确相等”不能伪称为写接口已经具备的保证。

## 4. 耐久性与权限检查的保证限度

执行顺序为：输入/身份/本人写许可 → 耐久 reserve → 重验授权 → 耐久 dispatched → 再验授权与绑定 → 最多一次上游尝试 → 重验授权 → 耐久 finish → 令牌/预算检查 → 尝试交付 ACK。

dispatched 是“可能派发”的本地记录，不是上游送达证明。崩溃可能发生在派发标记与真实请求之间，也可能发生在真实执行与终态落盘之间；因此未知目标保持占用。operation_id 不发送给未证明支持幂等的旧接口，不承诺跨 T100、SQLite 与客户端的原子性或 exactly-once。

最后策略重验位于 finish 前，finish 后检查令牌、预算和取消状态；不宣称最后一次策略检查至响应交付间不存在撤权竞争。ACK 可以已记录 succeeded，但因超时、认证失效或连接中断未交付调用者；不能把这种客户端失败当作重新写入的许可。返回不包含员工资料。预算也不保证耐久收尾一定在 10 秒内返回。

候选 HTTP 401/403 被分类为 rejected；这是离线契约行为，真实接口必须另行证明拒绝且无副作用。其他不明确的派发后失败按 unknown 锁定。终态持久化失败保留未决，不能从没有终态推断没有请求。现阶段不实现自动核对、强制解锁或恢复框架。

双目标占用只覆盖共享同一操作库的企业调用；禁止用同企业多库或旧库恢复绕开占用。独立写运行单元默认单 worker，状态不可与查询 journal 混用。未来扩展并发或部署拓扑必须重新证明该不变量。

## 5. 验收与开放顺序

1. 完成纯离线契约：合成可信身份、独立员工/账号映射、动态 key、模拟上游实际报文捕获，以及持久状态/事件核对；包括并发、拒重、撤权/改绑、耐久失败、超时、取消与未知结果锁定。
2. 用项目独立环境运行一次性本机原生 MCP 直接验证，命令与场景见 [历史专用说明](../projects/biz-t100/docs/history/20260930/password-reset.md#6-离线直接验证)。它只证明合成直接链路，实际结果写入 VALIDATION-reset，不升级真实集成状态。
3. 取得并验证专用重置或无其他副作用的局部更新契约、真实身份与员工/账号关系、服务认证拒绝、密码安全交付及强制更改机制；在获准环境完成两名真实员工各自本人验收和未知结果调查流程，方可记录重置 business-validated。
4. 按独立写服务准入 GOV，限定工具白名单与 private endpoint，核对直接/两跳行为及错 key、工具/服务停用时 BIZ 业务请求为 0，单独记录 published。

离线 biz-validated 不依赖真实 IdP 或 T100。真实 business-validated 与 GOV published 是相互独立的证据维度，均不能由网关容器健康、只读通过、旧执行成功码或离线模拟替代。
