# ADR-001：短中期 MetaMCP + FastMCP，按业务逐个接入

日期：2026-09-29。依据：用户明确优先采用较简单的MetaMCP作为短中期GOV。

## 决定

- **GOV：MetaMCP 2.4.22。** 作为统一控制面，维护服务登记、环境地址引用、namespace、endpoint、工具暴露和组合验证；详细边界见 [ADR-004](架构决策-004-GOV统一服务注册与发布.md)。
- **CORE：Python 3.12 + FastMCP 4.0.10 + Pydantic 2 + uv。** 使用原生Tool、类型Schema、HTTP传输、Client和认证扩展；pytest验证、Ruff检查，每个项目独立锁定依赖。
- **BIZ-ADP：每个业务系统一个独立FastMCP项目。** 安装CORE包，每系统声明用户/委托/服务账号模式，原业务API按实际执行身份授权；独立项目不强制独立进程，运行单元按信任与风险边界决定。T100模式以后续[ADR-003](架构决策-003-T100服务账号授权.md)为准。
- **ContextForge：后续评估项。** 只有MetaMCP出现明确无法满足的治理需求时再评估；本次不初始化第二套产品配置或部署。

CORE是轻量库，不新增一跳网络服务，不复制FastMCP协议栈和Tool注册器。当前只建立服务工厂和工程探针；出现实际复用需求后再提取执行、审计、关联等公共能力。

模块间只通过公开包、MCP/HTTP契约和去敏发布描述交互；GOV不导入BIZ源码，BIZ不读取MetaMCP内部数据库，CORE不包含业务语义。新增模块按 [模块边界与接口约束](模块边界与接口约束.md) 声明职责、不变量、扩展点、失败边界和兼容策略。

## 为什么以MetaMCP开始

用户优先考虑简单、可快速建立短中期主线。MetaMCP提供现成的服务→namespace→endpoint组织方式，适合先聚合少量独立FastMCP业务服务。这个取舍把投入集中在业务工具和原系统权限验证；不代表MetaMCP已满足全部长期治理要求。

ContextForge1.0.11已有较完整治理能力及新的现代协议支持，但不作为本阶段启动条件。保留其版本来源供未来有具体缺口时评估即可。

## 协议与身份边界

MetaMCP2.4.22固定依赖TS SDK1.16.0，当前协议候选是 **2025-06-18 Streamable HTTP握手模式**。FastMCP4支持与旧客户端协商，因此底座同时验证该握手路径与自身现代模式。

这是一项明确的短中期兼容Profile调整：网关组合按其实际协议验收；原项目 `2026-07-28` 目标保持未通过状态，不拿自动fallback或现代CORE单组件测试抵扣。若后续必须端到端现代协议，再单独验证MetaMCP升级或其他产品。

API Key用于endpoint访问控制；OAuth/OIDC登录也不能直接说明原员工身份已可靠传到Adapter。真实业务开放前必须明确身份来源、客户端归因、凭据隔离及所选执行模式，保持受控调用和可追踪。T100按ADR-003使用服务管理员身份，BIZ限制本人查询，不把它当员工OBO或原员工权限继承。

## 首批范围与后续顺序

1. **本次：最小工程基础。** 根说明/规范、GOV选型入口、独立CORE项目及可验证探针；不预建所有模块。
2. **网关工程接入：MetaMCP→CORE。** 已有MetaMCP实例运行，先核对并固定其镜像及隔离配置，再注册工程探针的服务/namespace/endpoint，验证list/call、API Key拒绝、停用及协议版本；此时只签收工程连通，不重建既有实例。
3. **随后：首个BIZ-ADP。** 确定真实系统、执行模式、允许/拒绝对象和只读API；先验证直连，再接网关。T100已明确服务管理员模式，验收原API服务级限制与BIZ本人隔离，不再要求员工T100凭据差异。
4. **按业务扩展。** 只读闭环后增加低风险写入的确认、幂等和未知结果核对，完成原一期一读一写。

本地探针仅loopback且无业务I/O；业务服务要求显式AuthProvider。Provider存在不等于委托、授权或审计通过。旧仓库保持封存，分析报告仅作为历史资产，不整体迁入旧实现或运行环境。

## 旧资产的选择性复用

执行 [REUSE-01旧模块复用准则](旧模块复用准则.md)：当前所需能力先检查旧项目资产，再与框架原生能力及最小新实现比较。已满足当前边界并经验证的代码优先复用；接口或环境不符的部分先适配、再验证；只适合借鉴的部分保留设计/测试参考，不搬入运行代码。

复用服务于当前MetaMCP＋FastMCP主线，不因旧代码的框架、数据库、目录结构或历史计划反向改变当前选型与阶段范围。不整体迁入旧实现不等于一律重写；实际提取须有来源、依赖闭包、目标项目和新环境证据。

## 后续推进

用户指定 account_mt_v2 后，首个 T100 候选的限定离线开发与后续系统扩展按 [ADR-002](架构决策-002-首个T100服务与扩展.md) 推进。当前GOV产品实例已运行，T100独立组件开发与GOV组合验收分别记录，不据组件通过跳过网关、身份与真实权限验收。
