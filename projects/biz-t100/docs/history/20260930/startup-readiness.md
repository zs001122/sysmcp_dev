## 2. 查询：可进入受控运行装配，尚非开箱即测

[create_runtime_app](../../../src/biz_t100/runtime.py:218) 已创建真实 T100EmployeeClient，包含原生MCP生命周期、本地健康、单进程并发限制和查询审计。它是显式依赖的ASGI工厂，不负责监听；[CLI](../../../src/biz_t100/cli.py:16) 没有常驻启动命令。

仍需落地的最小工作：

1. **常驻只读入口**：装配配置加载、AuthProvider验签材料及ASGI宿主，明确本次绑定地址、端口和单worker停止方式。现有两个direct脚本为一次性自检，不能当作可交给人工持续调用的运行服务。
2. **受控模拟签发者配置**：独立模拟issuer、密钥/验钥材料、audience、client、scope和短期令牌。经原生AuthProvider验证，不能复用自检中的即时令牌或共享API key。
3. **批准的本人映射与服务配置**：将获准模拟主体绑定到本次圈定的两名员工档案号，准备拒绝对象；依据已定位的旧测试来源交付固定企业/报文字段和独立服务key文件。已有资料只需评估和受控交付，不能把旧源码内联key当作当前私密配置已装配。
4. **私有持久目录**：指定服务账号、policy/key文件与独占journal路径。数据库无需预先手工创建，lifespan会准备新库；缺库本身不是前置阻塞，私有目录和文件边界必须符合契约。

正式个人IdP不是此阶段只读测试的阻塞项。[身份设计§4.1](../../../../../docs/可信个人身份与本人映射设计.md:74) 已确认受控模拟签发者可用于只读运行装配、真实上游查询以及网关机制验证。结果只能记“模拟身份链路验证”；真实个人身份与business-validated仍未通过。模拟签发者不得用于真实写操作。

## 3. 重置：工程启动通过，真实执行仍未就绪

[create_reset_app](../../../src/biz_t100/reset_server.py:253) 可生成独立写服务，已实际完成本机端口测试。但 [T100PasswordResetClient](../../../src/biz_t100/reset_client.py:65) 在未显式注入transport时返回business_adapter_not_ready，没有已交付真实重置runtime。

这是默认装配限制，不是操作系统禁网。不得通过注入真实HTTP transport绕过尚未关闭的接口差距：

- 旧服务user.account.create兼具新增/修改，旧实现还默认提交账号启用字段。
- 文档要求状态字段，当前最小password patch是否被接受、是否只改密码尚未证实。
- code=0仅为应答，无目标读回、密码交付或生效证明。
- 需真实写身份、独立账号归属/许可及仅重置接口契约；已授权的模拟签发者只读范围不包含它。

对应事实和验收见 [password-reset.md](../../password-reset.md) 与 [RU-003](../../../../../docs/reuse/RU-003-T100本人密码重置.md)。重置可继续离线测试，不随查询入口一同开放。

## 4. 下一步顺序与判定

先落实查询最小常驻入口和受控输入，再执行本地check-config、启动、health/ready与MCP工具发现；此时仅证明服务已启动。

随后按已批准测试对象进行真实只读调用：A/B分别精确返回本人、前置拒绝零上游、服务key有效/失效、单条精确目标、撤权及审计。错误key和真实返回行为是需要实测的判定项，不能要求先完成这些验收才允许开始验收；发生不符合项就记录缺口，不将其写成通过。

直接链路取证后再做MetaMCP登记/白名单/private endpoint及两跳对照。模拟身份可验证传递机制，但不能升级成真实身份可信或最终published。

本轮同步纠正AGENTS、operations和integration-inputs中“必须先有正式IdP才能开始本阶段查询”的旧措辞，沿用已确认的模拟签发者决定，未新增授权范围。
