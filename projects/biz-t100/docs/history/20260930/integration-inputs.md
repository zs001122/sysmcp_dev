## 3. 仍需开发维护方定标的接口契约

1. **查询行为。** 旧文档声明 `employee_no` 支持模糊匹配。下发受控完整工号后，需要核对真实返回是否唯一且为同一目标；无记录、多条或错目标均按当前契约拒绝，不选第一条，不扩为姓名查询或批量筛选。
2. **结果与错误。** 已知成功依据为 `payload.std_data.execution.code == "0"`。维护方提供当前查询失败、凭据失效及服务级拒绝的 HTTP/业务码语义，以及返回字段、员工状态含义和只读副作用说明。未知码保持上游错误，不能解释成无权或空成功。
3. **实际认证。** [历史记录](/data/projects/account_mt/t100/README.md:92)称 2026-09-09 错误 key 仍执行；本轮已复测：随机错误key仍返回批准目标档案，当前认证有效项未通过。维护方需说明当前 key 校验与服务级限制；若 key 仍不参与校验，就如实记录该事实，不将错误 key 成功计为认证通过，也不把服务管理员模式当作认证证明。
4. **凭据交付与变更。** 明确当前私密文件位置、维护责任和 key 更新/撤销的实际生效边界。本人授权通过后才能读取 key，故障不回退旧值、旧入口或其他系统凭据。

第 1–3 项是已授权真实只读测试需要记录的判定项，不要求先获得真实验收通过记录才能开展验证；启动前仍须落实固定目标、批准映射、凭据交付与本地运行装配。接口定标不预设另建代理或改造接口服务；本仓仅维护 BIZ 调用适配。已确认的 HTTP 测试环境无需重复选择，但它不能抵扣当前尚无证据的认证项。

## 4. 个人身份与两员工授权输入

旧来源的共享入口 Token、姓名参数和固定审计 actor 不构成可信个人身份。当前选定的临时路径是独立受控模拟签发者：模拟主体通过原生 AuthProvider 验签后，按批准的 issuer+subject 映射到员工号；不从姓名结果、普通 Header、MetaMCP API Key 或 T100 管理员 key 推导身份。

本阶段按公开 AuthProvider / IdentityProfile 边界装配模拟 issuer、单一资源 audience、subject/azp、有效期、只读 scope 和有效性/撤销方式；独立生成签名密钥并受控保存，由可信公钥或 JWKS 验签。模拟 issuer/主体必须显式标记且不与正式身份混用。正式来源到位后按身份设计替换配置，并验证模拟 token 已被拒绝；不为本次测试重建登录系统。

授权维护方从已确认名单中圈定本轮两名获准对象，落实模拟主体到其档案号的批准映射、允许客户端及只读许可，并安排未获准、停用和改绑场景。资料通过受控文件交付，不在聊天或仓库提交个人映射真值。不需要两份员工 T100 凭据；相同服务 key 可以用于两个主体各自已授权的精确目标。

模拟身份可用于 MetaMCP 两跳机制实测，核对直连和两跳得到的 Caller 语义一致；endpoint API Key 不能替代身份签名或客户端归因。结果只记“模拟身份链路验证”，不得据此签收真实个人身份或 business-validated。模拟 token 仅用于既定只读范围，不得进入真实写操作或作为正式身份失效后的回退。

## 5. 分层验证与判定

| 层次/顺序 | 验证内容 | 通过证据与当前状态 |
|---|---|---|
| 离线运行准备 | 显式 http-test、默认 HTTPS、配置格式、固定目标、授权后读取 key、唯一目标检查及去敏失败 | 用隔离测试证明当前实现；结果记入相应验证记录，不算真实业务通过 |
| 接口定标 | 在已确认测试范围核对精确目标响应、真实业务码、服务 key 与服务级限制 | 后续另行执行；历史错误 key 放行记录未现场复核，当前不签收上游认证 |
| 模拟身份直连真实上游 | 两个获准模拟主体分别查询批准映射的员工档案；未映射/未许可/停用前置拒绝；改绑重验及审计 | 单员工已完成，第二员工待安排；前置拒绝没有新增上游尝试，真实返回与审计已核对；不记真实身份通过 |
| 真实身份直连验收 | 正式可信调用者分别查询其本人员工档案，并复验许可、撤权、服务认证与审计 | 等真实身份来源及归属证据到位后独立验收 business-validated；不阻塞上一阶段 |
| 网关组合 | 固定制品和协议，登记/namespace/private endpoint，验证身份传递、工具启停及结果与直连一致 | 模拟身份可先对照直连做机制实测；真实身份可信结论保留，GOV published 按其独立准入证据记录 |

成功还须满足当前查询记录契约：开始记录耐久提交后才调用上游，终态提交失败不交付业务成功，凭据和完整员工档案不入记录。故障/超时不得自动重试或宣称上游未执行；有开始无终态的请求仅供人工核对。

business-validated 须具备可信真实个人身份、BIZ 两员工本人隔离、上游当前认证/限制的准确证据与可核对记录；GOV published 另按登记、入口及两跳准入证据判定，二者不能替代。模拟身份配真实上游、测试入口确认或 HTTP 调用成功均保留其有限结论，不将整体状态改为通过。

当前已交付受控真实运行配置、批准的单员工映射并执行真实只读查询；未执行写操作。首个只读闭环也不代表原一期低风险写入目标已经完成。

## 新增本人密码重置的独立输入

v0.4 的重置工具先完成离线候选验证，实际运行不能套用本页只读许可，临时模拟签发者的 token 不得用于真实重置。真实准入须由接口维护方提供只重置、不新增账号、不启用账号、不改角色/权限的明确接口与验证证据；受控账号归属、密码交付与强制更改规则也须定标。旧 `user.account.create` 文档要求状态且无账号读回，当前不能证明最小密码 patch 可用。专用默认网络路径保持未就绪；详见 [密码重置契约](../../password-reset.md) 与 [RU-003](../../../../../docs/reuse/RU-003-T100本人密码重置.md)。
