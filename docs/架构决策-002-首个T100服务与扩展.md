# ADR-002：首个 T100 只读服务与后续业务扩展

日期：2026-09-29。状态：确定本轮开发边界；实现及验收结果以目标项目 `VALIDATION.md` 为准，本文不声明测试或真实业务通过。

## 1. 决定与依据

首个业务项目为 `projects/biz-t100`，只发布一个无业务参数的工具 `get_my_t100_employee_record()`。使用 Python 3.12、FastMCP 4.0.10 和 CORE 的公开服务工厂；T100 报文、业务模型、授权接线和查询审计由该独立项目维护。短中期 GOV 继续使用 MetaMCP，沿用 [ADR-001](架构决策-001.md)。

本次是有边界的离线开发包：适配已评估的报文与校验规则，实现异步客户端和最小持久查询记录，验证包与接口；不连接真实环境，不迁入旧凭据、配置、数据库或现场运行脚本。用户现已明确T100服务管理员执行模式，授权分层按[ADR-003](架构决策-003-T100服务账号授权.md)。真实凭据装配、受控本人许可与跨网关员工身份仍待验证，开发包不能据此进入真实运行路径。

复用范围和来源字节以 [RU-001：T100 本人员工档案](reuse/RU-001-t100本人档案.md) 为准，项目组织及安全不变量沿用 [BIZ-ADP 开发规范](BIZ-ADP开发规范.md)。本文将此前“候选未确定”的准备状态推进为“T100 候选已指定、可进行限定离线适配”，不表示真实业务准入已通过。

来源的具体依据：

- [T100 原报文实现](/data/projects/account_mt_v2/src/account_service/t100.py:40)：固定服务 `employee.list.data.query.get`、精确 `employee_no` 查询和唯一目标匹配。
- [来源返回模型](/data/projects/account_mt_v2/src/account_service/models.py:42)：员工档案与登录账号状态是不同事实；原 `account_id` 由入参回填，不能当作上游已验证事实。
- [来源 MCP 边界](/data/projects/account_mt_v2/docs/FastMCP接入与验收.md:33)：原应用只接受现代协议，不能直接作为 MetaMCP 兼容入口复用。
- [来源业务接入缺项](/data/projects/account_mt_v2/docs/接入条件与当前进度.md:75)：T100 真实只读未验收，OA 真实接口尚未完成。

来源仓没有可用 HEAD；不得补造提交号或仅凭旧测试报告认定当前包通过。RU-001 记录的文件摘要用于固定此次复用来源。

## 2. 工具与模块边界

工具输入为空对象，不接受工号、主体、客户端、Token、凭据引用、系统 URL 或额外业务参数。可信调用者由认证上下文取得，目标员工和业务调用资格由受控授权端口解析。

输出为类型化 `QueryResult(request_id, data)`；`data` 是 `EmployeeRecord`，仅包含 `system=t100`、`employee_id`、显示名、部门、员工状态和 `observation=employee_record`。不返回未经原系统证明的 `account_id` 或账号启停状态，不把员工状态改名为账号状态。对应模型见 [目标模型](/data/projects/sysmcp_dev/projects/biz-t100/src/biz_t100/models.py:32)。

只复用报文与校验行为，不搬入账号申请、审批、密码重置、停用、建号、整个 HTTP API 或登录诊断工具。OA 后续具备真实接口和合法调用条件时另建 `projects/biz-oa`；当前不创建 OA 空项目，也不建设跨业务大注册表。

服务工厂必须显式注入以下依赖，不能提供默认允许实现或自动读取旧环境：

| 依赖 | 输入、输出与职责 | 不承担 |
|---|---|---|
| `AuthProvider` | 使用 FastMCP 原生认证扩展验证本资源调用凭据，提供可信调用上下文 | 不以网关 API Key 自动推定员工身份或业务授权 |
| `EmployeeAccess` | `authorize(Caller) → EmployeeGrant`；核对调用者、本人映射、工具许可和版本，按显式service-account提供服务key；在耐久登记后、查询返回后重新核对 | 不从工具参数推导身份；服务key是明确执行模式，不因用户无权而回退放行 |
| `EmployeeReader` | `read(EmployeeGrant) → EmployeeRecord`；执行已批准的 T100 查询、唯一目标校验及字段映射 | 不管理网关目录，不扩大业务权限，不执行写 API |
| `QueryJournal` | 按请求、调用者、目标与阶段登记事件，耐久提交完成后才返回 | 不保存凭据或完整员工响应，不充当通用审计平台 |

接口依据见 [目标端口](/data/projects/sysmcp_dev/projects/biz-t100/src/biz_t100/ports.py:10)。CORE 只创建原生 FastMCP 对象，既不实现这些业务端口，也不增加一跳网络服务，见 [CORE 工厂](/data/projects/sysmcp_dev/projects/core/src/sysmcp_core/service.py:7)。

正常调用顺序为：认证 → 解析本人授权 → 耐久登记开始 → 重验授权 → 精确 T100 查询 → 重验授权并核对目标 → 耐久登记结果 → 返回类型化结果。前置拒绝或开始记录失败时，上游请求必须为零；业务已经查询后发生撤权、结果处理或终态记录失败，不能返回成功，也不能声称没有调用过上游。

## 3. 最小具体实现

T100 客户端使用异步 HTTP；固定目标、方法、服务名和报文形状，不接受调用方 URL，不跟随重定向，不继承系统代理，不关闭 TLS 校验。落实总预算、有界响应、取消及资源关闭，默认不重试。企业 ID、主机字段及服务字段属于独立运行配置；`key` 或 `host.acct` 的存在本身不证明员工委托。

响应必须匹配唯一的本人 `employee_no`，只映射已定义字段。HTTP 错误和业务错误按契约分别处理；未知业务码归为未确认的上游错误，不猜测为“无权”“无此人”或空成功。接口负责人确认错误码后再增加明确映射。

查询审计先采用本项目自有的最小 SQLite 实现，记录请求及开始、成功、失败或取消阶段。这里的“只读”指 T100 业务操作，SQLite 仍需写入耐久审计。调用前记录失败即拒绝；调用后记录失败保留开始记录供核对，不自动重放。该实现不承诺防篡改、分布式事务、高可用或生产灾备，不引入旧 FND 存储与恢复体系。

FileServiceAccountAccess已按ADR-003补齐受控本人配置与服务key提供；真实配置和身份Provider装配仍须另行验收。测试中的合成身份、凭据和 HTTP 替身只能证明接口行为，不能包装成可访问真实业务的默认启动配置。

## 4. 独立制品、协议与集成

每个业务项目拥有自己的 `pyproject.toml`、`uv.lock`、虚拟环境、测试、文档及构建产物。T100 安装已构建的 `sysmcp-core` wheel，通过公开 API 使用 CORE；当前依赖声明见 [项目定义](/data/projects/sysmcp_dev/projects/biz-t100/pyproject.toml:7)。不通过源码路径、`sys.path` 或旧仓目录实现运行时复用。CORE 的 wheel 已存在不等于 T100 包已经构建或验收。

协议验证分开记录：

| 验证路径 | 需要证明 | 当前声明 |
|---|---|---|
| 原生握手兼容路径 | 在原生 HTTP 上按 `2025-06-18` 完成 initialize、工具发现和调用；记录实际版本、Schema、错误及认证拒绝 | T100组件已验证；具体证据见VALIDATION，不代替MetaMCP组合 |
| 现代协议路径 | 在同一服务的原生能力上验证 `2026-07-28` 的发现、调用与拒绝 | 单独验证，不抵扣网关组合 |
| MetaMCP → T100 | 固定网关/服务制品及两跳协议，验证 namespace/endpoint、API Key 拒绝、工具启停和真实员工身份承载 | 未执行，不以自动回退或单组件结果签收 |

不复制来源仓限制为现代协议的自制 HTTP 边界；在原生 FastMCP 传输上实现并验证当前兼容 Profile。原有端到端现代协议目标仍保持未通过，短中期兼容路径不替代它。

MetaMCP 由 GOV 统一配置：登记实际服务制品和环境地址引用，将服务组成 namespace，再发布为 endpoint，并记录工具白名单与组合证据。BIZ-T100通过去敏发布描述提供服务ID、制品版本、协议、工具契约和身份承载要求；T100服务key、员工映射、允许清单与审计数据始终留在BIZ。聚合与工具启停不改变业务服务的授权规则；网关内部 API、数据库模型和 namespace 名称不进入 CORE。网关 Key 只用于入口访问控制，不能替代员工资源身份或T100服务凭据，各层必须分开验证。具体流程见 [ADR-004](架构决策-004-GOV统一服务注册与发布.md)。

## 5. 后续 OA、CRM 等如何接入

后续每系统分别声明并验证per-user/delegated/service-account；T100的管理员模式不推广到其他系统。只有业务候选明确且通过复用评估后，才建立 `projects/biz-<system>`。各服务保持自己的 API 客户端、业务模型、配置、凭据来源和持久数据；例如 T100 凭据不能出现在 OA/CRM 配置中，各服务不直接查询彼此数据库表。相同框架不要求所有系统共用账号、凭据、表结构或运行进程。

各工具在所属项目的 `docs/tool-contracts.md` 定义稳定名称、用途、读写属性、输入输出 Schema、错误、时限、身份条件和审计字段；依赖版本与发布制品逐项目锁定。破坏性契约修改使用新的接口版本或工具名称并给出迁移窗口，不在同一已发布名称下静默改变字段或权限语义。

GOV集成层记录实际服务制品、工具契约版本和网关映射，解决工具重名及发布范围；只为已提交并准入的服务建立目录项，不为尚未接入的系统建立空注册表。只有多个已运行业务服务出现同类、稳定且被验证的需求时，才评估提取到 CORE；T100 字段、报文、错误码和业务授权始终留在 BIZ 项目。

## 6. 验收顺序与当前缺口

1. **独立包与模块契约。** 在自身环境完成安装、静态检查、构建和离线测试；确认仅有一个无参数只读工具，额外参数拒绝、输出字段白名单、精确目标匹配、异步预算/取消与去敏错误符合契约。
2. **调用与审计边界。** 验证无身份、缺映射、撤权、错目标及审计前置失败的零上游请求；验证调用后故障不伪报未执行或成功，SQLite 重开后可核对开始/终态记录。
3. **两种原生 HTTP 协议。** 分别验证上一节兼容与现代路径，记录实际版本；验证身份/业务替身不会进入正式运行装配。
4. **真实输入定标。** 确认接口责任人、指定测试环境、报文/错误码、本人映射与许可依据、服务key装配及上游服务限制；确认网关之后如何可靠承载员工身份与客户端来源。T100分别验证原API服务key有效/失效，以及两个MCP用户的本人隔离、未授权零请求；不要求两个员工T100凭据。
5. **网关与真实只读闭环。** 在明确范围的新环境固定制品并接入单一服务；验证发现/调用/停用、错误 Key、身份替换、撤权、真实权限及审计。原系统拒绝应记录已发生的调用，前置拒绝才要求上游请求为零。

当前尚缺第 4 项真实输入和跨网关身份方案，第 5 项未执行；本轮只推进前 3 项对应的开发和离线验证。任何实际结果写入项目 `VALIDATION.md`，注明已执行、未执行及证据范围，不以来源仓历史验证替代本轮结果。

只读闭环通过后，再按实际业务需求单独设计低风险写入、具体操作确认、原系统原子授权、幂等和未知结果核对；首个只读服务不代表原一期“一读一低风险写入”完成。
