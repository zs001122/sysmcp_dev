# ADR-009：T100账号启停与密码重置接入

日期：2026-09-30。用户要求MetaMCP查询入口之外也能执行账号禁用、启用和密码重置。用户进一步明确同一MCP服务承载功能，只通过端点区分工具。本决策替代ADR-008本阶段的读写两单元部署选择；四接口业务语义保持不变。

## 接入与业务对象

复用BIZ-T100现有account_maintain／user.account.create。gzxastus=N／Y控制登录账号；password_reset=Y明确请求密码重置。员工档案status不参与账号启停，也不用于验证账号效果。

一个FastMCP实例在明确Docker桥接地址8781承载四接口；GOV仅登记sysmcp-t100一个服务，查询／账号两个namespace及private endpoint分别选择t100_employee_query、t100_account_maintain。三项账号操作共用一个工具，不增加三个服务器。不同调用者的scope与目标许可仍在BIZ检查，不复制上游key或业务规则到GOV。

本阶段上游凭据与信任域一致，采用单实例便于开发和运维；四接口共享进程故障与发布节奏。以后出现不同凭据／信任域再按实际需求拆部署，不将按功能拆进程当固定规则。

## 最小授权

共享内部连接主体的动作仅employee_query＋account_maintain，员工／账号对沿用已批准范围；account_profile=status-password仅允许五个master字段：gzxastus、gzxa001、gzxa003、is_reproduce、password_reset。

| 请求 | gzxastus | password_reset | is_reproduce |
|---|---|---|---|
| 禁用 | N | N | N |
| 启用 | Y | N | N |
| 启用状态下重置密码 | Y | Y | N |

该连接拒绝复制、detail（包括空数组）、角色／作业／据点维护和禁用同时重置；原本机完整维护的full配置保持兼容。工具发现按部署动作、验签scope和主体许可交集返回；直接调用未授权工具仍前置拒绝。scope、动作、目标、profile均通过后才读取T100管理员key，历史未决和审计规则不变。

产品新增maintenance模式，并为query＋account主体签发仅这两个scope的共享连接令牌；要求禁止宽泛搜索、员工范围和账号目标非空、账号员工属于批准查询范围、status-password策略。查询范围与账号对分别批准，查询许可不自动授予写许可。旧read/write配置及签发保持兼容，最长1小时，不输出令牌、不访问T100，不签任意写管理员身份。

## 验收与阶段边界

先以合成身份验证三种报文及拒绝边界，再核对三份真实本人用例的服务端授权（不读取key、不连接上游），登记网关并验证工具发现、缺confirm、错误Key及启停。已有手测写入事实保留，不因登记自动重复密码重置。

日常继续使用offline.py／live.py。账号ACK仅表明上游回执，实际账号启停／密码效果需要账号资料或登录证据；临时静态连接仍不代表外部用户。真实个人身份、business-validated、published继续独立验收。

复用范围为RU-007已评估的当前产品工厂、接口客户端、审计、远程入口与受支持MetaMCP管理API；没有引入旧项目执行代码或许可。当前验证见 [v0.9.1](../projects/biz-t100/VALIDATION-v0.9.1.md)。
