规则：[REUSE-01](../旧模块复用准则.md)。初评日期：2026-09-29；当前修订：2026-09-30，BIZ-T100 v0.7.0。最新用户确认员工档案是查询、更新及用户资料新增/修改的前提；启用/禁用修改员工资料 `status=Y/N`，两者均须回读；`employee.data.update` 只传员工号和 status 时，省略的其他字段保持。

## 3. 当前输入、输出与接口契约

| 接口 | 输入与边界 | 输出与完成条件 |
|---|---|---|
| employee.list.data.query.get | 固定企业，授权 employee_no；is_digiwin_product=N，use_has_next=false | 恰好一条员工、工号完全相等；用于存在性前查及状态回读 |
| employee.data.update | `employee-status-v1`，员工数组仅 employee_no/status；公共 is_digiwin_product=N | 总 code 为严格 0，恰好一条结果，source_no/erp_no 均全等授权工号，execute_description 为空；然后再查询目标状态 |
| user.account.create | `legacy-account-v1` 密码重置；受控 gzxa001/gzxa003，显式 gzxastus、is_reproduce=N、password_reset=Y；省略 detail | 保持严格 ACK 契约，结果 upstream_acknowledged；不证明密码生效、登录或交付 |

状态更新的唯一员工体如下，示例全为合成数据：

```json
{
  "is_digiwin_product": "N",
  "employee": [{"employee_no": "E001", "status": "N"}]
}
```

启用固定 Y、禁用固定 N。不发送空姓名、空部门或查询取得的全量资料，不因上游支持模糊查询而放松本人目标校验。员工与账号归属按授权绑定关联；查询 account_no 为空不表示未绑定，也不能用该字段自动覆盖绑定。姓名仅用于展示，判断使用企业＋员工号。

启停成功须同时满足前查存在、写回执有效、唯一员工回读目标状态、授权再次通过及终态审计成功，才返回 `business_verified`、`business_effect_verified=true`。密码重置仍只有 ACK；回读状态匹配也不证明密码已重置。临时身份在所有结果中仍为 `real_identity_verified=false`。

文档差异继续明确记录：查询 date_s/date_e 的必填标记与已验证无日期报文不同；is_digiwin_product 示例 Y 不要求当前运行改值；用户资料 is_reproduce 有尾随空格排版差异，当前使用无空格规范键；部分 JSON 样例缺括号。员工更新逐条回执与账号 ACK schema 不混用，也不从排版样例推导新增默认字段。

| 旧员工更新入口 | 仅参考协议字段和风险记录 | 旧多匹配、仅判断全局 code 和状态覆盖历史不足以闭环；当前重写限定两字段客户端 |

| 当前身份与授权原语 | 复用并增加启用 action | 原生 FastMCP 验签、独立 scope、受控 employee/account 绑定、授权后读 key；查询权限不能转换为写许可 |
| 当前耐久写状态机 | 最小扩展 | 三动作共享库，保留开始/派发/终态、重验及未知结果占用，不重写成新的账号平台 |

最小依赖仍为当前 FastMCP/CORE、已锁定 Python 库、明确注入的 AuthProvider/身份、受控授权、T100 配置及共享操作库。CORE 不承载 T100 状态语义；GOV 只登记准入工具，不保存业务绑定、key 或审计。新增代码成本集中在有限状态客户端及契约测试，低于迁入整套旧平台；回退时停用入口而保留历史，不删库恢复运行。

## 5. 授权、迁移与失败边界

启用工具 `enable_my_t100_account` 使用 `t100:account:enable:self`；禁用与重置各保留自身工具和 scope。三者不能互借许可，远程工具输入只有 confirm/operation_id；本机指定目标先转为独立受控快照并经原生验签、授权，再读取管理员凭据。

`employee-status-v1` 要求 `employee_update_omissions_preserved=true`、`employee_status_updates_enabled=true`（两项默认 false），同时满足共同内部测试开关、存在性确认、非空证据引用、企业/上游摘要与精确目标动作状态白名单。账号重置继续要求独立 detail 保留确认。当前真实私有配置已设置 `legacy_status_writes_enabled=false` 禁止旧账号接口启停重发；历史记录仍可调查，密码重置不受此开关替代。原批准目标新增 enable＋Y 独立白名单，重置仍仅允许 N；没有扩展其他员工或账号。

SavedPlan 将上游 Profile 纳入批准快照，历史缺省为 legacy-account-v1；同 UUID 不得换接口、动作、工号、账号或状态。已有员工前查不是建档授权；查询途中撤权时发写前再次拒绝。异步授权后再次检查令牌有效期；更新后授权变化或回读异常不返回业务成功。专用 EmployeeStatusReceipt 携带已验证员工/账号/状态，普通 ResetReceipt 不能冒充状态回读；本机 status-results 独立保存请求次数与成功观测，取证失败不报业务成功。

同一企业的三个动作使用原持久操作库；索引跨动作占用员工和账号，unknown 不能靠新 UUID、另一动作、重启或新库绕过。数据库派发标记是保守事实，前查失败可能零次实际写但仍保留 unknown；输出单独记录 read_attempts/write_upstream_attempted。结果不明不自动重发、解锁或移除记录。

上游 key 认证仍是独立缺口：历史真实只读中错误 key 仍放行，不能由写 ACK 或状态回读推定写接口认证有效。不能对真实账号盲发错误 key 写请求来证明拒绝。密码结果也未定标，不复用旧“密码等于工号”推定，不采集密码用于文档或自动测试。
