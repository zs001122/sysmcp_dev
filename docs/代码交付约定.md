# CORE 与 BIZ-T100 代码交付约定

日期：2026-10-08。本轮为 BIZ-T100 0.9.2 候选交付收尾；版本及验收结果以各项目的实际声明和验证记录为准。

## 首次提交候选范围

当前根目录作为工作空间版本库；CORE、BIZ-T100、GOV 继续独立管理依赖、测试与制品。首次提交候选包括根 README、STATUS、AGENTS、workspace.toml、忽略规则、架构与复用记录，以及已评估的各项目公开源码、锁文件、合成配置模板、部署模板、测试和去敏验证说明。历史公开分析可保留来源，不作为当前通过证据。

提交前逐项核对候选清单：不得纳入 `.runtime`、`.venv`、环境秘密、私钥、令牌、真实员工资料、服务 key、审计库或个人业务请求／回执。原 DOCX 和运行证据留在现有私有位置；不删除、不迁入版本库。`dist/` 不进入源码提交；各项目制品按版本及 SHA-256 单独交付，旧版本不覆盖。

## 检查与审查标准

[GitHub Actions 候选工作流](../.github/workflows/biz-t100.yml) 在 CORE、BIZ-T100 及相关交付规则变化时，使用 Python 3.12、uv 0.11.26 和两个独立锁文件：先检查及测试 CORE、构建 CORE wheel，再锁定安装 BIZ、检查代码并运行 `offline.py --suite all`，最后构建和检查 BIZ 制品。CORE wheel 必须符合 BIZ 锁文件摘要，不能为通过检查静默改锁。失败时停止交付，不运行 `live.py`、常驻服务、真实 T100、MetaMCP 或旧运行入口，不读取已有私有运行资料。

产品 wheel 不含测试、脚本或运行材料；源码包可含公开测试、脚本和文档，但同样不含私有运行资料。CI 仅上传边界检查通过的包、摘要及保留用例名／结果计数的 JUnit 摘要，不上传原始 XML、捕获输出或运行目录。文件边界与私钥／令牌格式检查不能替代人工确认所有业务内容已去敏。

代码审查至少覆盖四接口对象与输入输出、身份／员工号／管理员凭据边界、授权前零凭据读取和零上游请求、员工更新原字段保留、写入未知结果占用、审计失败处理及制品内容。审查结论必须绑定具体提交和检查结果；本地检查、历史测试及用户手测不能记录成远端 CI 或正式版本审查已通过。

## 提交与发布状态

目前未配置远端仓库；该工作流是 GitHub 落点候选，远端首次运行、分支保护和 PR 审查尚未完成。后续确定其他托管平台时按同一检查契约适配，不臆造已有 GitHub 仓库或 CI 运行记录。

[AGENTS.md](../AGENTS.md) 明确约定：“常规本地构建、测试和修复可直接进行。新环境实际部署按任务授权范围开展；不自动提交或推送。”因此本轮可以准备可审查的候选、验证及说明，不自动创建提交、推送或部署；提交和推送须有用户明确授权，正式审查状态另行取证。

源码归各独立项目；CORE 通过正式 wheel 被 BIZ 安装，不跨项目导入内部源码。GOV 仅保留登记与发布关系，业务秘密、映射、授权和审计仍归 BIZ。CI 通过证明声明的离线交付检查，不自动提升真实业务或 GOV 发布验收状态。
