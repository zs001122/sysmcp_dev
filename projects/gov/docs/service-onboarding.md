# GOV 服务接入规范

更新日期：2026-09-30。选型基线：MetaMCP 2.4.22。BIZ-T100 **0.9.1** 当前由一个 FastMCP 实例和一个 MetaMCP MCP server 登记承载，查询／账号两个 namespace 及 private endpoint 分别暴露对应工具。内部登记和门禁组合已验证，正式个人身份与完整发布验收仍未完成。当前接入见 [查询与账号接入](t100-account-onboarding.md)，运行事实见 [部署记录](../部署记录.md)；[早期只读接入](t100-internal-onboarding.md) 保留为历史。

## 1. 目的

本规范定义 BIZ 服务如何交付给 GOV，以及 GOV 如何在不接管业务实现和秘密的前提下完成 MetaMCP 登记、组合、发布和验证。架构归属见 [ADR-004](../../../docs/架构决策-004-GOV统一服务注册与发布.md)。

| 层次 | 职责与边界 | 当前 T100 对应 |
|---|---|---|
| BIZ 独立项目 | 源码、依赖、业务契约、授权、上游适配、审计及制品的管理边界 | `projects/biz-t100` |
| FastMCP 运行单元 | 实际业务工具进程；按凭据、信任域、风险、容量与发布节奏选择 | 一个 `maintenance` 实例承载四工具 |
| MetaMCP MCP server | 网关对下游 MCP 服务的连接登记，引用地址、协议及受控连接身份 | 一个 `sysmcp-t100` 登记 |
| namespace | 组合登记的服务并选择对外可见工具 | query／account 两个 namespace，各启用一个工具 |
| private endpoint | 提供 namespace 的网关访问地址及入口认证 | query／account 两个 private endpoint |
| 工具与业务操作 | 工具由 BIZ 定义，操作由合法业务参数表达，GOV 只选择发布范围 | 账号禁用／启用／重置共用 `t100_account_maintain` |

增加业务操作不自动增加 MCP server 或进程；增加 endpoint 也不表示新增业务服务。GOV 的 `catalog/` 是去敏登记与核验索引，引用 BIZ 公开发布描述和工具契约，不导入 BIZ 源码、不维护员工／账号映射或业务策略。

## 2. BIZ 交付包

每个服务由所属 BIZ 项目提交 `docs/service-release.md`，至少包含：

| 字段 | 要求 |
|---|---|
| 服务标识 | 稳定逻辑ID、所属系统、用途、负责人和运行单元边界 |
| 制品 | 包/镜像名称、不可变版本或摘要、构建证据、启动方式、回滚版本 |
| 地址 | 各环境地址引用、MCP路径和网络前提；秘密及受控真值不入库 |
| 协议 | Streamable HTTP、目标协议 Profile、initialize 要求、超时、健康检查；直连与网关兼容 Profile 分别说明 |
| 工具 | 允许暴露的工具名、契约版本、读写属性、输入/输出Schema摘要 |
| 身份 | 资源受众、可信主体与客户端如何到达BIZ、业务执行模式 |
| 证据 | 组件、HTTP、原生MCP、权限与审计中已执行和未执行的项目 |
| 运维 | 停用、回滚、容量、已知限制、故障联系人和生效窗口 |

不得交付上游业务密钥、MetaMCP密钥真值、员工映射、授权允许清单、完整业务响应、业务审计数据库或BIZ源码副本。GOV只保存受控引用和去敏证据。

GOV 入口 Key、BIZ 可信资源身份凭据和上游服务 key 分别归属各层。GOV 所需下游连接令牌只在受控私有运行配置中管理，不写入公开目录；签名私钥、目标许可和上游 key 始终留在 BIZ。

## 3. GOV 接入顺序

1. **受理**：检查实际用例、服务负责人、发布描述完整性、复用评估和BIZ状态；不为未来系统创建占位登记。
2. **登记**：在目标环境登记实际FastMCP地址，记录MetaMCP对象ID、制品版本、协议和配置摘要。
3. **发现**：完成 initialize 与工具发现，对照 BIZ 当前主体可见工具、公开契约、Schema 和错误；服务完整实现不等于连接主体获准全部工具，未知工具默认不发布。
4. **组合**：在服务暴露前固定限定 namespace 的工具白名单，处理名称冲突，记录服务／工具启停结果；多个 namespace 可以引用同一个服务登记，不因此扩大各自白名单。
5. **发布**：创建或更新private endpoint；启用API Key，禁用匿名和URL查询参数密钥。
6. **验证**：分别比较声明 Profile 下的直连与两跳发现／调用；验证错误 Key、身份替换、白名单外工具直接调用、停用、超时、错误归属和下游业务请求数。工具发现和健康检查不算业务请求；失败后不自动重放真实写入。
7. **签收**：分别记录GOV发布状态和真实业务验证状态；任一失败不得用另一项成功抵扣。

实际 MetaMCP 操作方式以固定版本可验证能力为准。若只能通过 UI 配置，就在本目录记录去敏步骤、对象 ID 和结果；使用 API 时按本固定版本已验证的受支持管理接口实施，不承诺跨版本稳定，也不臆造声明式导入格式。禁止直接修改 MetaMCP 内部数据库。

直连和网关协议分别签收。当前 T100 直连明确使用 `2025-11-25`，MetaMCP 2.4.22 使用 `2025-06-18` initialize 兼容 Profile，不用自动回退成功抵扣目标协议；原端到端现代协议目标仍保持未通过。实际操作统一引用 [BIZ 测试说明](../../biz-t100/docs/testing.md) 和 [常驻运行说明](../../biz-t100/docs/service-runtime.md)，本页不复制业务测试命令。

## 4. 状态记录

| 状态 | 判定 |
|---|---|
| `candidate` | BIZ候选已明确，未完成独立验证 |
| `biz-validated` | BIZ 独立制品及声明范围的离线逻辑／契约证据通过，不依赖真实身份或上游 |
| `gov-registered` | 实际地址、制品、协议和对象ID已登记 |
| `composed` | namespace和工具白名单已核对 |
| `published` | private endpoint、白名单、入口拒绝／启停及按声明身份契约的两跳治理验收通过；有端点不等于完成发布 |
| `disabled` / `retired` | 已停用或退役，记录原因、时间和影响 |

`business-validated` 独立记录真实可信身份、权威员工来源或唯一受控映射、真实上游、分层权限与业务审计是否通过。它与 `published` 是独立证据维度，不能互相推导；临时合成身份、账号 ACK 或容器运行均不能替代真实验收。测试集合和实际调用次数按对应版本记录，不将历史全量结果算作当前相关回归。

## 5. 变更与隔离

- 工具增删、Schema、身份、错误或副作用变化先更新BIZ契约和发布描述，再更新GOV白名单。
- 只改BIZ内部实现且契约不变，也要固定新制品并完成服务自身回归；GOV按影响决定是否重跑两跳测试。
- namespace或endpoint变更必须列出全部受影响服务并回归现有工具，不能让新模块静默扩大既有发布面。
- 共进程服务若新增管理员凭据、写能力、不同信任域或独立扩缩容需求，先评估实际凭据／信任边界、读写风险、故障影响和发布节奏。按 ADR-004 的隔离原则及经验证需求决定运行单元；需要隔离时拆分，保持合并时记录收益、隔离措施和回归证据，不把每个写动作直接等同新进程。当前 T100 同凭据、同信任域的单实例选择以 [ADR-009](../../../docs/架构决策-009-T100账号操作网关接入.md) 为准。
- 发布失败恢复到已记录的服务、namespace与endpoint版本；不得临时指向旧仓或未验证地址。

## 6. T100 当前接入范围

当前 `projects/biz-t100` 0.9.1为一个FastMCP实例，GOV只登记sysmcp-t100一个MCP server。query／account两个namespace及private endpoint分别选择员工查询和账号维护工具；账号禁用、启用、密码重置共用一个工具。工具名使用sysmcp-t100__前缀。原本人服务契约及历史证据保留，不将测试维护主体当真实员工。

实际对象已记录在 `catalog/`，当前状态为 `gov-registered`、`composed`。2.4.22 使用登记的临时连接 JWT，不透传外部用户 JWT；API Key 仅是入口凭据。正式个人身份、端到端用户授权及完整发布条件仍未验收，不能标为 `published` 或 `business-validated`。上游管理员 key、员工范围、授权策略和业务审计留在 BIZ；GOV 只保存去敏登记及组合证据。

| 当前 namespace／endpoint | 唯一暴露工具 | BIZ 连接范围 |
|---|---|---|
| `sysmcp-t100-internal-query` | `sysmcp-t100__t100_employee_query` | 仅批准员工的明确工号查询 |
| `sysmcp-t100-internal-account` | `sysmcp-t100__t100_account_maintain` | 批准员工／账号配对的禁用、启用及启用状态下重置 |

两个 namespace 共用查询＋限定账号维护的静态内部连接主体及短期 JWT，最长一小时，过期由 BIZ 续签并通过受支持管理界面／API 更新 MetaMCP Bearer token；自动更新工具尚未实现。该连接不代表外部真实员工，也没有员工建档／更新 scope。账号报文 profile 由 BIZ 管理，GOV 仅引用其公开边界，不复制目标名单或业务策略。

现版 MetaMCP Key 属于用户级凭据，不天然绑定某个 endpoint；两个端点分别配置 Key 不构成端点级身份隔离。各 namespace 白名单必须独立核验，跨端点直接调用另一工具应被拒绝；BIZ 仍执行自己的主体、scope 和目标授权。

本版 [0.9.1 验证](../../biz-t100/VALIDATION-v0.9.1.md) 记录 675 项相关离线回归及实际网关门禁，本次 T100 读写均为 0；此前真实查询两跳一致属于 [0.9.0 历史证据](../../biz-t100/VALIDATION-v0.9.0.md)。账号成功回执和用户手测反馈独立保留，实际启停／密码效果通过账号资料或登录确认，不能用员工档案 `status` 代替。

后续统一维护入口见 [DEC-001](../../../docs/项目讨论与决策记录.md)：已确认需求、尚未实现，计划通过公开管理契约分层下发和核验；总览只保存受控引用、配置版本和状态，不把身份映射、业务规则或上游凭据迁入 GOV。

## 7. 接入完成判定

只有以下条件同时满足，服务才可声明由GOV发布：固定产品和服务制品可追溯；工具白名单与Schema一致；错误入口凭据和停用能阻止新的业务执行；身份上下文按契约到达BIZ；直连与两跳的业务结果、错误和追踪可对照；回滚可执行。真实业务闭环还必须另有该系统权限、拒绝、撤权与审计证据。
