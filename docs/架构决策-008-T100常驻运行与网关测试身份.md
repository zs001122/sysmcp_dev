# ADR-008：T100 常驻运行与网关测试身份

日期：2026-09-30。依据：四接口已实现，用户报告手动测试通过，并同意“常驻FastMCP→实际客户端→MetaMCP→后续正式身份”的顺序。

## 决定与边界

BIZ-T100 增加薄运行装配与产品 serve 命令，原有四工具的输入、错误、业务执行、回读及未知写语义保持。产品不导入 scripts/tests；既有 live.py 增加网络调用，offline.py 继续承载离线验证，不恢复旧日常脚本。

默认运行单元为只读查询与写维护两个进程：查询只暴露 employee_query；写维护只暴露 employee_create、employee_update、account_maintain。部署工具集合同时限制发现与直接调用。两单元共享同项目原操作库与原未决库，避免拆进程后绕过占用；共享审计只发生在同一BIZ内，不跨模块读取。

每个调用者必须经原生JWT验签，服务侧许可绑定issuer／subject／client、企业、动作和员工／账号范围。调用者的工具参数只确定业务目标，不确定本人身份；常驻不按请求自动创建许可。内部签名私钥在私有客户端文件，服务只持公钥；T100服务key只在服务侧许可通过后读取。服务原配置许可的动态撤权继续生效。

原审计、历史事件、unknown和员工档案对象分类保留。请求、最终写报文、筛选回执与结果放同项目私有证据目录。读写可以同时运行；任一进程停用不自动重试未知写入。当前内部签发者仍为测试身份，不签收真实员工身份。

## 网络、协议与失败边界

代码默认loopback；实际查询地址可显式绑定Docker宿主桥接接口，使现有MetaMCP容器可达，写维护保持loopback。地址及端口归BIZ运行配置，GOV只保存环境引用；不会为了连通将业务key交给网关。未认证请求拒绝，健康只返回装配状态。退出以SIGTERM为准，不删除审计或运行资料。

客户端显式选择协议Profile，直连2025-11-25、MetaMCP候选2025-06-18分别握手核验，不拿自动回退抵扣。服务启动、工具发现、真实本人查询和网关组合分别取证；不重复此前已经手测的真实写入。

## MetaMCP 2.4.22 的已核实限制

现运行容器为2.4.22及固定revision32b6e981，SDK1.16.0。该版本没有新源码工作树的forward_headers能力；下游Authorization来自登记静态headers、OAuth令牌或bearerToken，不透传原调用者Authorization。

本阶段允许用独立受控内部连接客户端验证限定查询组合：BIZ验证它的签名、客户端和许可，API Key仅控制GOV入口。这个客户端表示网关连接身份，不代表原外部人，不能把所有网关用户归因为已认证员工。签名私钥、T100key和员工范围留BIZ；GOV目录只留连接身份模式和受控引用，资源连接认证材料不进入公开仓库。

只有真实登记和组合完成才记gov-registered／composed。外部用户身份承载、停用及完整两跳未通过时，不签published；正式IdP与真实员工验证属于后续独立阶段。不会为这个差异扩建新AI平台或立即改MetaMCP源码。

## 验证、兼容及回滚

合成测试验证工具集合、授权前key零读取、范围拒绝、撤权、证据和原未决检查；既有默认四工具回归保持。实际TCP检查健康、工具发现与批准本人只读，保留协议、请求和审计证据。构建0.9.0独立制品，保留0.8.4及更早文件；回滚停止新进程并使用原制品，不删库、不迁回旧项目。

复用结论见 [RU-007](reuse/RU-007-T100常驻服务与远程客户端.md)，GOV现场核对与接入方式在其项目记录。
